# AIPulse Web Dashboard v0.2 实施计划

> 版本：v0.2
> 日期：2026-07-09
> 目标：交付一个可独立运行、实时更新的 AI 热点 Web Dashboard，覆盖热点浏览、关键词管理、来源配置、每日摘要与任务调度五大模块。

---

## 一、背景与目标

### 1.1 背景

AIPulse 的核心数据层（`hotspot` 子系统）已经具备：

- 多源采集器注册与调度；
- `Source` / `Hotspot` / `Keyword` / `DailyDigest` 数据模型；
- 基于 LLM 的热点分析、热度评分与去重；
- SSE 实时事件推送；
- Obsidian 归档能力。

但此前缺少一个统一的 Web 前端来消费这些数据。v0.2 的目标是把后端能力完整封装为一个可访问的 Dashboard。

### 1.2 核心目标

1. 提供独立的 `web/` Vue 3 + Vite 前端工程，可通过 `pnpm dev` 开发、`pnpm build` 构建；
2. 实现五大页面：AI 热点、关键词、来源、定时任务、每日摘要；
3. 所有页面通过 REST API 与后端通信，支持 SSE 实时更新；
4. 保持与桌面端一致的「心电图纸 / 监测仪」视觉风格；
5. 提供单元测试与端到端测试骨架，核心视图覆盖渲染与交互。

### 1.3 验收标准

- [ ] `web/` 可独立构建并通过 `vue-tsc` 类型检查；
- [ ] Dashboard 首页可筛选、排序、分页浏览热点；
- [ ] 热点详情页展示摘要、元数据、相关推荐与 Obsidian 归档；
- [ ] 关键词页支持增删改、启用/停用、通知开关；
- [ ] 来源页支持编辑权重/同步间隔/JSON 配置、启停、手动同步；
- [ ] 定时任务页展示调度任务列表与日志；
- [ ] 每日摘要页可生成、浏览、切换历史摘要；
- [ ] 新增热点通过 SSE 推送到前端；
- [ ] 单元测试覆盖率不低于 70%（按 Vitest + jsdom）。

## 二、范围与边界

### 2.1 在范围内

- `web/` 前端工程初始化（Vue 3、Vue Router、TanStack Query、TypeScript、Vite）；
- 通用组件：`PulseLine`、页面布局、状态提示、表单控件；
- 五大视图页面及对应 API 客户端；
- 与 `src/aipulse/web/routes.py` 现有接口对接；
- SSE 客户端封装与热点列表自动刷新；
- 基础可访问性（焦点管理、ARIA 标签、skip-link、减少动画偏好）。

### 2.2 不在范围内

- 新增采集器（由热点系统优化计划负责）；
- 用户认证与权限；
- 服务端渲染；
- 移动端独立应用；
- 邮件/桌面通知（仅保留 SSE 推送，桌面通知后续迭代）。

## 四、UI/UX 设计

### 4.1 视觉主题

延续 AIPulse 桌面端的「监测仪」风格：

- 背景色 `--paper: #fcfaf8`；
- 淡粉色心电图网格 `--grid: #f2dadc`；
- 主文字 `--ink: #1b1a17`；
- 次要文字 `--slate: #7a756c`；
- 信号/强调色 `--signal: #d93025`；
- 字体：`Space Grotesk` + `PingFang SC` + `JetBrains Mono`。

顶部导航包含品牌标识 `AIPulse`、脉冲动画 `PulseLine`、状态文字「信号正常」以及五个导航链接。

### 4.2 页面布局

- 最大内容宽度 `880px`，水平居中；
- 页面标题 + 副标题 + 数据读数（如热点总数、活跃来源数）；
- 内容区使用 `panel` 卡片承载列表与表单；
- 状态提示统一使用 `.state-empty`、`.state-loading`、`.state-error`、`.state-success`。

### 4.3 响应式

- 断点 `640px`；
- 小屏下顶部导航换行、筛选器垂直堆叠、来源卡片改为垂直布局、摘要页侧边栏与内容上下排列。

### 4.4 可访问性

- 提供 `skip-link` 跳到主内容；
- 所有表单控件带 `label` 或 `aria-label`；
- 错误/加载状态使用 `role="alert"` / `role="status"` + `aria-live`；
- 按钮焦点环使用 `--signal` 色 box-shadow；
- 支持 `prefers-reduced-motion: reduce`。

## 五、API 对接

### 5.1 通用响应格式

后端统一返回：

```json
{
  "success": true,
  "data": { ... },
  "meta": { "total": 100, "page": 1, "limit": 20 }
}
```

`api/client.ts` 封装 `apiFetch<T>`，处理 `X-AIPulse-Token`、超时、HTTP 错误与 `success=false` 解析。

### 5.2 接口清单

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/hotspots` | 热点列表（搜索、筛选、排序、分页） |
| GET | `/hotspots/:id` | 热点详情 |
| GET | `/hotspots/:id/related` | 相关热点 |
| POST | `/hotspots/:id/archive` | 归档到 Obsidian |
| GET | `/keywords` | 关键词列表 |
| POST | `/keywords` | 新增关键词 |
| PUT | `/keywords/:id` | 更新关键词 |
| DELETE | `/keywords/:id` | 删除关键词 |
| GET | `/sources` | 来源列表 |
| PUT | `/sources/:id` | 更新来源配置 |
| POST | `/sources/:id/sync` | 手动触发同步 |
| GET | `/digests` | 历史摘要列表 |
| GET | `/digests/latest` | 最新摘要 |
| POST | `/digests/generate` | 生成今日摘要 |
| GET | `/sse/hotspots` | SSE 实时热点事件 |
| GET | `/scheduler/jobs` | 调度任务列表 |
| POST | `/scheduler/jobs/:id/run` | 立即运行任务 |
| POST | `/scheduler/jobs/:id/pause` | 暂停任务 |
| POST | `/scheduler/jobs/:id/resume` | 恢复任务 |
| GET | `/scheduler/logs` | 任务日志 |

### 5.3 SSE 实时更新

- `useSse('/sse/hotspots')` 在 `DashboardView` 挂载时建立连接；
- 收到 `hotspot.new` 事件后触发 `queryClient.invalidateQueries({ queryKey: ['hotspots'] })`；
- SSE 由 `SseManager` 管理，具备心跳（15s）与有界队列（64 条），队列满时丢弃最旧消息。

## 六、页面详细设计

### 6.1 AI 热点页（`/dashboard`）

**功能：**

- 默认按 `heat_score` 降序分页展示；
- 搜索标题/摘要（debounce 300ms）；
- 筛选：来源（news/github/arxiv/huggingface/social）、重要性（low/medium/high/critical）、分类（ai-models/ai-products/industry/paper/tip）；
- 排序：热度/时间，升序/降序切换；
- 分页：每页 20 条，URL query 与状态同步；
- 空态提示用户去关键词页添加关注词。

**实现要点：**

- 使用 `useQuery` 监听 `[page, debouncedQ, source, importance, category, sort, order]`；
- 筛选器变化自动回到第 1 页；
- URL query 双向绑定，支持刷新/分享当前视图。

### 6.2 热点详情页（`/hotspots/:id`）

**功能：**

- 展示标题、来源、分类、重要性、发布时间、热度分数；
- 展示 AI 摘要，支持跳转原始链接（URL 安全检查）；
- 提供「归档到 Obsidian」按钮；
- 底部展示相关热点列表。

**实现要点：**

- 使用 `useQuery` 获取热点与相关热点；
- 使用 `useMutation` 处理归档，成功后显示「已归档」；
- 原始链接通过 `isSafeUrl()` 校验，避免 `javascript:` 等危险协议。

### 6.3 关键词页（`/keywords`）

**功能：**

- 列表展示所有关键词；
- 添加关键词（输入框 + 回车/按钮）；
- 切换启用状态 `is_active`；
- 切换通知开关 `notify_on_match`；
- 删除关键词。

**实现要点：**

- 添加/更新/删除成功后刷新 `['keywords']` 查询缓存；
- 操作中的行显示 loading 状态。

### 6.4 来源页（`/sources`）

**功能：**

- 列表展示来源名称、类型、启用状态、权重、同步间隔、上次同步时间、最近错误；
- 点击「编辑」展开表单：权重、同步间隔（最小 5 分钟）、JSON 配置；
- 客户端校验权重为数字且 ≥0，同步间隔为整数且 ≥5；
- 启停来源；
- 手动触发同步。

**实现要点：**

- JSON 配置解析失败时聚焦 textarea；
- 同步按钮在来源停用或同步中禁用；
- 使用 `nextTick` 在校验失败后聚焦首个错误输入。

### 6.5 定时任务页（`/jobs`）

**功能：**

- 展示调度任务列表与最近日志；
- 支持立即运行、暂停、恢复任务。

**实现要点：**

- 操作成功后刷新 `['jobs']` 缓存；
- 立即运行任务时本地记录 running 状态以优化按钮反馈。

### 6.6 每日摘要页（`/digests`）

**功能：**

- 左侧边栏列出最近 10 条摘要；
- 右侧展示选中/最新摘要的 Markdown 内容；
- 提供「生成今日摘要」按钮。

**实现要点：**

- 未选中时默认展示最新摘要；
- 生成成功后刷新列表与最新摘要缓存。

## 七、后端适配需求

当前后端接口（`src/aipulse/web/routes.py`）已覆盖热点、关键词、来源、摘要、SSE。v0.2 计划要求后端保持稳定，如有必要进行以下补全：

1. **调度接口**：确保 `/scheduler/jobs`、`/scheduler/jobs/:id/run|pause|resume`、`/scheduler/logs` 存在并返回统一格式；
2. **错误信息脱敏**：`sanitize_error_message` 已用于 `source.last_error`，确保前端展示安全；
3. **跨域配置**：开发环境允许 `web/` 前端访问 `/api`，生产环境由 Tauri/反向代理统一处理；
4. **分页元数据**：`/hotspots` 返回 `meta.total/page/limit`，与前端分页组件对齐。

## 十一、风险与应对

| 风险 | 应对措施 |
|---|---|
| 后端接口不稳定 | 前端统一处理 `success=false` 与网络错误，给出明确提示 |
| 热点为空 | 空态引导用户添加关键词，并提示系统每 30 分钟同步 |
| SSE 连接断开 | 浏览器自动重连，前端不依赖 SSE 做唯一数据源 |
| 构建体积过大 | 按需引入依赖，Vite 自动 tree-shaking；必要时配置分包 |
| 移动端体验差 | 响应式布局 + 小屏断点优化，但不追求功能完全对齐桌面 |
