# AIPulse Web Dashboard v0.2 设计文档

> 版本：v0.2  
> 日期：2026-07-09  
> 状态：已实现，与 `main` 同步  
> 目标：为 AIPulse 热点子系统提供一套独立、实时、可筛选的 Web Dashboard，让用户在浏览器里每天花 5 分钟掌握 AI 领域动态。

---

## 1. 概述

### 1.1 背景

AIPulse 后端已具备完整的热点监控能力：

- 多源采集器注册与 APScheduler 调度；
- `Source` / `Hotspot` / `Keyword` / `DailyDigest` 数据模型；
- LLM 分析、热度评分、去重与摘要；
- SSE 实时事件广播；
- Obsidian 归档与每日摘要生成。

但此前缺少一个面向用户的 Web 前端来消费这些数据。v0.2 Web Dashboard 的目标是把上述后端能力封装为可独立运行、实时更新的可视化界面。

### 1.2 设计目标

1. 提供独立的 `web/` 前端工程（Vue 3 + Vite + TypeScript），与桌面端解耦；
2. 覆盖五大核心模块：AI 热点、关键词、来源、定时任务、每日摘要；
3. 所有数据通过 REST API 获取，热点更新通过 SSE 实时推送；
4. 延续 AIPulse 桌面端「心电图纸 / 监测仪」的视觉风格，形成统一品牌认知；
5. 支持筛选、排序、分页、归档、关键词管理、来源调度和摘要生成等高频操作；
6. 保持基础可访问性与响应式适配，并配套单元测试与端到端测试。

### 1.3 非目标

- 不新增采集器（由热点系统优化计划负责）；
- 不做用户认证与权限；
- 不做服务端渲染；
- 不做移动端独立应用；
- 不做邮件 / 桌面 Push 通知（仅保留 SSE 实时推送）。

## 2. 总体架构

### 2.1 系统上下文

```
┌─────────────────────────────────────────────┐
│            Web Dashboard (web/)              │
│   Vue 3 + Vue Router + TanStack Query + Vite │
│   浏览器 ← EventSource → SSE 实时更新        │
└──────────────────┬──────────────────────────┘
                   │ fetch /api/*
                   ▼
┌─────────────────────────────────────────────┐
│            FastAPI Web API                   │
│  /api/hotspots      /api/keywords            │
│  /api/sources       /api/digests             │
│  /api/sse/hotspots  /api/scheduler/*         │
└──────────────────┬──────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────┐
│         Hotspot Service + APScheduler        │
│  采集 → 去重 → 分析 → 评分 → 持久化 → 广播  │
└─────────────────────────────────────────────┘
```

### 2.2 前端技术栈

| 层级 | 选型 |
|---|---|
| 框架 | Vue 3.5+（Composition API + `<script setup>`） |
| 路由 | Vue Router 4.6+，`createWebHashHistory` |
| 状态/缓存 | TanStack Query 5.50+（`useQuery` / `useMutation`） |
| 构建 | Vite 8+，TypeScript 6.0+，`vue-tsc` 类型检查 |
| 测试 | Vitest + jsdom + `@vue/test-utils` |
| E2E | Playwright |
| 样式 | 原生 CSS 变量 + scoped Vue 单文件样式 |

### 2.3 数据流

1. 页面挂载时通过 `useQuery` 发起 API 请求，参数变化自动重新获取；
2. 修改类操作通过 `useMutation` 执行，成功后调用 `queryClient.invalidateQueries` 刷新相关缓存；
3. `DashboardView` 挂载时通过 `useSse('/sse/hotspots')` 建立 SSE 连接；
4. 收到 `hotspot.new` / `hotspot.updated` / `digest.ready` / `sync.completed` 等事件后，按事件配置失效对应 Query Key；
5. 浏览器自动处理断线重连，前端不依赖 SSE 作为唯一数据源。

## 3. 数据模型

### 3.1 Hotspot（热点）

后端模型：`src/aipulse/hotspot/models.py::Hotspot`  
后端 Schema：`src/aipulse/hotspot/schemas.py::HotspotOut`

```ts
interface Hotspot {
  id: string
  title: string
  url: string
  summary: string | null
  source_type: string
  heat_score: number
  importance: string
  category: string | null
  published_at: string | null
}
```

关键字段说明：

- `source_type`：采集来源类型，如 `news`、`github`、`arxiv`、`huggingface`、`social`；
- `importance`：LLM 判定的重要性，`low` / `medium` / `high` / `critical`；
- `category`：热点分类，如 `ai-models`、`ai-products`、`industry`、`paper`、`tip`；
- `heat_score`：热度分数，用于排序与可视化进度条；
- `url`：原始链接，前端展示前需经过 `isSafeUrl()` 校验。

### 3.2 Keyword（关键词）

后端模型：`src/aipulse/hotspot/models.py::Keyword`  
后端 Schema：`src/aipulse/hotspot/schemas.py::KeywordOut`

```ts
interface Keyword {
  id: string
  value: string
  is_active: boolean
  notify_on_match: boolean
  created_at: string
}
```

前端实际使用的最简类型位于 `web/src/types/index.ts`，未包含 `created_at`，但后端返回完整字段。

## 4. API 契约

### 4.1 通用响应格式

```json
{
  "success": true,
  "data": { ... },
  "meta": { "total": 100, "page": 1, "limit": 20 }
}
```

`api/client.ts` 中的 `apiFetch<T>` 负责：

- 读取 `import.meta.env.VITE_API_BASE_URL`（默认 `/api`）与 `VITE_API_TOKEN`；
- 若存在 Token，附加请求头 `X-AIPulse-Token`；
- 10 秒请求超时；
- HTTP 错误与 `success=false` 统一抛出 `ApiError`。

### 4.2 REST 接口清单

| 方法 | 路径 | 用途 | 前端调用位置 |
|---|---|---|---|
| GET | `/api/hotspots` | 热点列表（搜索、筛选、排序、分页） | `api/hotspots.ts::fetchHotspots` |
| GET | `/api/hotspots/:id` | 热点详情 | `api/hotspots.ts::fetchHotspot` |
| GET | `/api/hotspots/:id/related` | 相关热点 | `api/hotspots.ts::fetchRelatedHotspots` |
| POST | `/api/hotspots/:id/archive` | 归档到 Obsidian | `api/hotspots.ts::archiveHotspot` |
| GET | `/api/keywords` | 关键词列表 | `api/keywords.ts::fetchKeywords` |
| POST | `/api/keywords` | 新增关键词 | `api/keywords.ts::createKeyword` |
| PUT | `/api/keywords/:id` | 更新关键词 | `api/keywords.ts::updateKeyword` |
| DELETE | `/api/keywords/:id` | 删除关键词 | `api/keywords.ts::deleteKeyword` |
| GET | `/api/sources` | 来源列表 | `api/sources.ts::fetchSources` |
| PUT | `/api/sources/:id` | 更新来源配置 | `api/sources.ts::updateSource` |
| POST | `/api/sources/:id/sync` | 手动触发同步 | `api/sources.ts::syncSource` |
| GET | `/api/digests` | 历史摘要列表 | `api/digests.ts::fetchDigests` |
| GET | `/api/digests/latest` | 最新摘要 | `api/digests.ts::fetchLatestDigest` |
| POST | `/api/digests/generate` | 生成今日摘要 | `api/digests.ts::generateDigest` |
| GET | `/api/scheduler/jobs` | 调度任务列表 | `api/scheduler.ts::fetchJobs` |
| POST | `/api/scheduler/jobs/:id/run` | 立即运行任务 | `api/scheduler.ts::runJob` |
| POST | `/api/scheduler/jobs/:id/pause` | 暂停任务 | `api/scheduler.ts::pauseJob` |
| POST | `/api/scheduler/jobs/:id/resume` | 恢复任务 | `api/scheduler.ts::resumeJob` |
| GET | `/api/scheduler/logs?limit=50` | 任务执行日志 | `api/scheduler.ts::fetchLogs` |
| GET | `/api/sse/hotspots` | SSE 实时热点事件 | `composables/useSse.ts` |

### 4.3 `/api/hotspots` 查询参数

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `q` | string | `""` | 标题模糊搜索（`title ILIKE %q%`） |
| `source` | string | `""` | 按 `source_type` 过滤 |
| `importance` | string | `""` | 按 `importance` 过滤 |
| `category` | string | `""` | 按 `category` 过滤 |
| `sort` | string | `heat_score` | 排序字段：`heat_score` / `published_at` |
| `order` | string | `desc` | 排序方向：`asc` / `desc` |
| `page` | int | `1` | 页码，从 1 开始 |
| `limit` | int | `20` | 每页条数 |

### 4.4 SSE 事件类型

事件注册与处理逻辑位于 `web/src/composables/useSseHelpers.ts`：

| 事件 | 说明 | 处理动作 |
|---|---|---|
| `hotspot.new` | 新增热点 | 失效 `['hotspots']` 缓存 |
| `hotspot.updated` | 热点更新 | 失效 `['hotspots']` 与 `['hotspot']` 缓存 |
| `digest.ready` | 摘要就绪 | 失效 `['digests']` 与 `['digest', 'latest']` 缓存 |
| `sync.completed` | 来源同步完成 | 失效 `['sources']` 与 `['jobs']` 缓存 |

SSE 连接具备指数退避重连：初始 1 秒，最大 30 秒；后端心跳间隔 15 秒，订阅队列上限 64 条。

## 7. 页面详细设计

### 7.1 AI 热点页（`/dashboard`）

`views/DashboardView.vue`：

- **数据读数**：右上角展示热点总数 `meta.total`；
- **搜索**：输入框 `q`，`300ms` 防抖（`useDebounce`）；
- **筛选器**：来源、重要性、分类，三列 `<select>`；
- **排序**：字段（热度 / 时间）+ 升序/降序切换按钮；
- **分页**：上一页 / 下一页，仅当 `totalPages > 1` 显示；
- **URL 同步**：所有筛选、排序、分页状态通过 `router.replace({ query })` 同步到 URL，支持刷新与分享；
- **实时更新**：挂载时调用 `useSse('/sse/hotspots')`；
- **空态**：提示用户前往「关键词」添加关注词，系统每 30 分钟同步。

### 7.2 热点详情页（`/hotspot/:id`）

`views/HotspotDetailView.vue`：

- 返回按钮回到上一页；
- 标题区展示来源、分类、重要性、发布时间、热度分数；
- 主体面板展示 AI 摘要，无摘要时显示「暂无摘要」；
- 安全链接「访问原始链接」，新标签页打开并带 `rel="noopener noreferrer"`；
- 「归档到 Obsidian」按钮，调用 `POST /api/hotspots/:id/archive`，成功后显示「已归档」；
- 底部展示相关热点列表（同分类优先，否则同来源）。

### 7.3 关键词页（`/keywords`）

`views/KeywordsView.vue`：

- 顶部读数展示已有关键词数量；
- 输入框 + 添加按钮，空值禁止提交；
- 列表支持：开启/关闭通知、启用/停用、删除；
- 添加/更新/删除成功后刷新 `['keywords']` 缓存；
- 独立展示添加错误与删除错误。

### 7.4 来源页（`/sources`）

`views/SourcesView.vue`：

- 顶部读数展示活跃来源数；
- 列表项展示名称、类型、启停状态、权重、同步间隔、上次同步时间、最近错误；
- 点击「编辑」展开内联表单：权重（≥0）、同步间隔（≥5 分钟）、JSON 配置；
- 客户端校验失败后聚焦首个错误输入（`nextTick` + `safeFocus`）；
- 启停按钮直接更新 `is_active`；
- 「立即同步」按钮仅在来源启用且未同步中时可用。

### 7.5 定时任务页（`/jobs`）

`views/JobsView.vue`：

- 展示调度任务列表与最近 20 条日志；
- 立即执行时本地记录 `running` 状态优化按钮反馈；
- 暂停 / 恢复操作成功后刷新 `['jobs']`。

### 7.6 每日摘要页（`/digests`）

`views/DigestsView.vue`：

- 左侧边栏列出最近 10 条摘要，可点击切换；
- 右侧展示选中/最新摘要的标题、生成时间、正文；
- 正文按行分段渲染为 `<p>`；
- 右上角「生成今日摘要」按钮，生成成功后刷新列表与最新摘要缓存；
- 默认未选中时展示最新摘要。

## 8. 交互与行为细节

### 8.1 筛选与排序

- 任意筛选条件变化时自动回到第 1 页；
- 排序方向切换不影响页码；
- 搜索输入 300ms 防抖，避免频繁请求。

### 8.2 URL 状态同步

`DashboardView` 通过双向 `watch` 实现：

- 组件状态变化 → `router.replace({ query })`；
- 外部 URL 变化（如前进/后退）→ 解析 `route.query` 回写组件状态。

### 8.3 安全链接

`lib/url.ts`：

```ts
export function isSafeUrl(url: string): boolean {
  try {
    const parsed = new URL(url)
    return parsed.protocol === 'http:' || parsed.protocol === 'https:'
  } catch {
    return false
  }
}
```

热点卡片与详情页均使用该校验，禁止 `javascript:` 等危险协议。

### 8.4 错误处理

- 后端 `sanitize_error_message` 会去除 `source.last_error` 中的 URL、路径、Token 等敏感信息；
- 前端统一使用「信号中断」「接口异常」等文案，并提示检查后端服务；
- 操作错误（如添加关键词失败、JSON 配置解析失败）单独展示在行内或表单下方。

### 8.5 开发环境代理

`vite.config.ts` 配置：

```ts
server: {
  port: 5174,
  strictPort: true,
  host: 'localhost',
  proxy: { '/api': { target: 'http://localhost:8000', changeOrigin: true } },
},
```

生产环境由反向代理或 Tauri 统一处理跨域。

## 9. 可访问性与响应式

### 9.1 可访问性

- 提供 `skip-link` 跳到主内容；
- 所有表单控件带 `label` 或 `aria-label`；
- 错误/加载状态使用 `role="alert"` / `role="status"` + `aria-live="polite"`；
- 按钮焦点环使用 `--signal` 色 `box-shadow`；
- 导航链接当前态使用 `aria-current`（Vue Router 默认）；
- 支持 `prefers-reduced-motion: reduce`，禁用动画。

### 9.2 响应式

- 断点 `640px`；
- 小屏下：
  - 顶部导航换行，PulseLine 换到下一行；
  - 筛选器垂直堆叠；
  - 热点卡片与来源卡片改为垂直布局；
  - 摘要页侧边栏与内容上下排列；
  - 关键词操作按钮右对齐。
