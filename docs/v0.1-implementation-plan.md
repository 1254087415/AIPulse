# AIPulse v0.1 实现计划

> 状态栏优先的独立 macOS app，Tauri + Python sidecar 架构。

---

## 1. 目标与范围

### v0.1 核心目标

把一个独立的 macOS 状态栏 app 跑通：

1. 点击状态栏图标弹出输入框
2. 粘贴 RSS/视频/文章链接
3. 自动下载/提取内容
4. 生成中文摘要
5. 归档到 Obsidian
6. 飞书 / 微信通知

### 进入 v0.1 的功能

- 状态栏输入链接触发处理
- 视频平台解析：YouTube、Bilibili、抖音、小红书
- 文章平台解析：微信公众号、普通网页（作为增强）
- RSS 源订阅与同步
- 本地 SQLite 任务/元数据存储
- Obsidian 归档（源笔记 + 总结笔记）
- 飞书 Webhook 推送
- 微信公众号消息推送（博主更新提醒）
- 处理进度展示

### 不进入 v0.1 的功能

- Web 看板
- iOS App / 快捷指令
- 浏览器扩展
- 热点聚合与去重
- 知识库向量化（v0.2）
- 邮件 / Slack 等其他推送渠道

| UI | Tauri + Vue/React 前端框架 | macOS 状态栏、弹窗、通知 |
| 进程通信 | JSON-RPC over stdin/stdout | Tauri 启动 Python sidecar |

| 通知 | 飞书自定义机器人 Webhook、微信公众号模板消息 | 参考 feishu-push / wechat-push skill |

## 4. 模块设计

### 4.1 Tauri 侧

**main.rs**
- 创建状态栏图标
- 注册全局快捷键（可选）
- 启动 Python sidecar
- 退出时清理 sidecar

**python_runner.rs**
- 查找 Python 可执行文件（开发时用 `.venv/bin/python`，打包时随 app 分发）
- 启动 `src/desktop/sidecar.py`
- 维护 stdin/stdout 读写
- 处理 sidecar 崩溃重启

**commands.rs**
- `submit_url(url: String) -> Result<TaskId, Error>`
- `get_task_status(task_id: String) -> Result<TaskStatus, Error>`
- `retry_task(task_id: String) -> Result<(), Error>`
- `get_settings() -> Result<Settings, Error>`
- `update_settings(settings: Settings) -> Result<(), Error>`

**menu.rs**
- 状态栏图标右键菜单
- 快捷入口：打开 Obsidian 归档文件夹、打开设置、退出

### 4.2 Python Sidecar

**sidecar.py**
- 从 stdin 读取 JSON-RPC 请求
- 分发到对应 handler
- 异步执行 handler，stdout 输出 JSON-RPC 响应/通知

**JSON-RPC 协议**

请求：
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "submit_url",
  "params": {"url": "https://...", "source": "menubar"}
}
```

响应：
```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {"task_id": "uuid"}
}
```

进度通知（服务端主动推送）：
```json
{
  "jsonrpc": "2.0",
  "method": "task_progress",
  "params": {"task_id": "uuid", "status": "downloading", "message": "..."}
}
```

### 4.3 设计模式应用

v0.1 统一使用以下设计模式，保证后续扩展性：

| 场景 | 模式 | 文件位置 | 说明 |
|---|---|---|---|
| 视频/文章解析器 | **策略 + 工厂** | `video/parsers/*`, `article/*` | 按 URL 域名匹配解析策略，新增平台只需注册新策略 |
| 字幕获取 | **策略 + 工厂** | `video/subtitle/*` | Bilibili 官方字幕、yt-dlp 内嵌字幕、faster-whisper ASR 可自由组合 |
| 推送渠道 | **策略 + 工厂** | `pushers/*` | 飞书、微信、邮件等推送策略可插拔 |
| LLM Provider | **适配器 + 工厂** | `summarizers/base.py`, `factory.py`, `llm.py` | OpenAI / OpenRouter / 本地模型统一接口 |
| 处理流水线 | **模板方法 + 观察者** | `core/pipeline.py` | 固定处理步骤，进度通过事件通知 Tauri |
| 内容类型识别 | **职责链** | `core/content_router.py` | 依次判断 URL 是视频/文章/RSS/其他 |
| Obsidian 笔记 | **建造者** | `archive/builder.py` | 分步构建 frontmatter + 正文 |
| 任务重试/日志 | **装饰器/代理** | `core/decorators.py` | 解析器外包裹重试和日志 |
| 配置/数据库 | **单例** | `core/config.py`, `store/database.py` | 全局唯一实例 |
| 数据访问 | **仓储** | `store/repository.py` | 隔离 SQLAlchemy，业务层不直接操作 ORM |

### 4.4 视频解析器接口（策略模式）

```python
class ContentParser(ABC):
    @property
    @abstractmethod
    def supported_domains(self) -> list[str]: ...

    @abstractmethod
    async def can_parse(self, url: str) -> bool: ...

    @abstractmethod
    async def parse(self, url: str, work_dir: Path) -> ParsedContent: ...
```

```python
class ParserRegistry:
    def register(self, parser: ContentParser) -> None: ...
    def resolve(self, url: str) -> ContentParser | None: ...
```

### 4.5 字幕获取策略

```python
class SubtitleStrategy(ABC):
    @abstractmethod
    async def fetch(self, video_info: VideoInfo, work_dir: Path) -> SubtitleResult: ...

class BilibiliSubtitleStrategy(SubtitleStrategy): ...
class EmbeddedSubtitleStrategy(SubtitleStrategy): ...
class WhisperSubtitleStrategy(SubtitleStrategy): ...
```

字幕策略工厂按平台选择策略：
- Bilibili 优先用 `BilibiliSubtitleStrategy`
- YouTube / 通用平台用 `EmbeddedSubtitleStrategy`
- 无字幕时用 `WhisperSubtitleStrategy`

### 4.8 处理流水线（模板方法 + 观察者）

```python
class ContentPipeline(ABC):
    async def run(self, task: Task) -> None:
        await self._notify("parsing")
        content = await self._parse(task)

        await self._notify("transcribing")
        transcript = await self._transcribe(content)

        await self._notify("summarizing")
        summary = await self._summarize(transcript)

        await self._notify("archiving")
        await self._archive(content, summary)

        await self._notify("pushing")
        await self._push(summary)

        await self._notify("done")

    @abstractmethod
    async def _parse(self, task: Task) -> ParsedContent: ...
    @abstractmethod
    async def _transcribe(self, content: ParsedContent) -> str: ...
    @abstractmethod
    async def _summarize(self, transcript: str) -> SummaryResult: ...
    @abstractmethod
    async def _archive(self, content: ParsedContent, summary: SummaryResult) -> None: ...
    @abstractmethod
    async def _push(self, summary: SummaryResult) -> None: ...
```

观察者：`PipelineObserver` 接口，用于向 Tauri 发送 `task_progress` 通知。

### 4.11 视频处理细节

- 视频平台由 `ParserRegistry` 解析
- 每个平台决定自己的字幕策略：Bilibili 用平台 API，YouTube 用内嵌字幕，抖音/小红书用 ASR
- 解析器返回 `ParsedContent`，流水线继续处理

### 4.12 文章提取器

复用 `obsidian-video-summary/scripts/web_extract.py` 的思路：
- 微信公众号：`single-file-cli` 渲染
- 普通网页：`defuddle` 或 `jina.ai` reader 备用
- v0.1 中文章提取作为增强，优先级低于视频

### 4.13 转写器

- 优先使用已有字幕
- 无字幕时用 faster-whisper small 本地 ASR
- 输出纯文本 transcript

### 4.14 总结器

- 输入 transcript + title
- LLM 输出 JSON：`{summary, key_moments}`
- 按 `obsidian-video-summary` skill 规范生成总结笔记

### 4.15 Obsidian 归档

遵循 skill 规范：
- 源笔记放入 `工作学习/已归档/<平台>/`
- 总结笔记放入 `工作学习/AI/AI总结文档/`
- 文件名：`YYYY-MM-DD-标题.md`
- 双向链接：`source_note` / `summary_note`
- frontmatter 用英文 snake_case

### 4.16 飞书推送

复用 `feishu-push` skill 的加签逻辑：
- 支持 webhook + secret
- 处理完成/失败都推送

### 4.17 微信推送

复用 `wechat-push` skill：
- 微信公众号模板消息
- 用于 **RSS 订阅的博主更新提醒** 和 **手动提交的视频/文章处理完成通知**
- 配置：appid、appsecret、模板 ID、openid
- 飞书主要用于处理完成/失败的状态通知，微信用于博主更新提醒和处理完成的轻量提醒

## 6. 处理流程

### 6.1 状态栏提交链接

1. Tauri 收到 `submit_url`
2. 通过 JSON-RPC 发给 Python sidecar
3. sidecar 创建 `Task`，status = `pending`
4. sidecar 返回 `task_id`
5. Tauri 订阅 `task_progress` 通知
6. sidecar 异步执行处理流水线
7. 完成后 sidecar 发送 `task_complete` 通知
8. Tauri 显示系统通知

### 6.2 视频处理流水线

```
URL
  ↓
识别平台（Bilibili / 抖音 / 小红书 / YouTube / generic）
  ↓
调用对应 VideoParser.parse()
  ↓
如有视频且无字幕：提取音频 → faster-whisper 转写
  ↓
LLM 生成 summary + key_moments
  ↓
生成 Obsidian 源笔记 + 总结笔记
  ↓
飞书推送
  ↓
Task status = done
```

### 6.3 RSS 同步

- APScheduler 定时拉取 RSS
- 识别条目中的视频/文章链接
- 自动创建 Task
- 用户首次添加 RSS 后可选择是否自动处理
